全部在本机测量。修复前后的应用内数据来自两个打包产物交替各跑两次（旧：仓库里的 1.7.0；新：本分支构建）。

|---:|---|---|
| 100 | 0.37 ms → 0.10 ms | 0.26 ms → 0.10 ms |
| 1,000 | 2.6 ms → 0.4 ms | 2.6 ms → 0.12 ms |
| 4,000 | 6.9 ms → 约 2 ms | 6.6 ms → 0.22 ms |

| 100 | 0.58–0.60 ms | 0.40–0.44 ms |

| 2,000 | 6.2–6.3 ms | 4.8–4.9 ms |
| 4,000 | 13.6–19.5 ms | 10.4–12.6 ms |

| 编号 | 级别 | 问题 | 状态 |
|---|---|---|---|
| PERF-01 | 中 | 每次编辑的开销随片段数线性增长 | **部分**：编辑核心自己的那一份去掉了（上表）。应用里 4,000 片段仍约 11 ms 一步，剩下的是界面对每次状态变化的响应，**没有定位到具体订阅者** |
| PERF-02 | 中 | 编组片段同步最坏 O(n²) | **已修复**（每组只列一次；有性能守卫测试） |

| PERF-04 | 中 | 媒体库磁盘占用无上限 | 未处理（新功能，本轮不做） |
| PERF-05 | 信息 | 冷启动 | 见下 |
| PERF-06 | 低 | 测试耗时 | 未处理 |

第一次尝试 PERF-01（提交 `dad9106`）是错的：它让“不改片段的命令”变快，却让改片段的命令从 6.9 ms 变成 11.4 ms。测出来之后由 `eb086e7` 替换。两个提交都留在历史里。

启动时间波动很大，本轮没有得出结论：同一个构建，热启动 0.4 s 出页面、0.8–1.1 s 画出界面；但刚构建完或隔了一阵没运行时，出现过 18 s 才出页面、30 s 才画完，以及超过 30 s 页面未出现。怀疑是安全软件扫描未签名的可执行文件，**没有证实**。

| 播放：视频加声音 | **没有结论**，见下 |

**播放的问题没有查清。** 视频加声音的时间线在 5 次自动运行里，1 次完全流畅，其余 4 次播放头前进不均匀，而且表现各不相同：一次 `requestAnimationFrame` 每秒只触发一次而 CPU 96% 空闲（像是窗口被遮挡时的节流，未证实）；一次主线程有最长 1.2 秒的停顿，12% 的 CPU 花在主包里一个没能识别的函数上，垃圾回收占 9%；一次页面定时器停了约 20 秒，期间播放头按音频时钟走到了结尾；另一次 2 秒只前进了 29 帧。流畅的那次与其余几次的一个区别是：同一次运行里之前没有做过导出。这些运行都是在后台自动启动的窗口里做的，可能受桌面上其他窗口影响。

**把窗口提到前台后重测（4 次）：**

| 运行 | 每秒绘制帧数 | 定时器最长间隔 | 播放头 |
|---|---:|---:|---|
| 本次运行里没有先导出，第 1 次 | 60 | 55 ms | 每 0.5 秒 15 帧，均匀 |
| 本次运行里没有先导出，第 2 次 | 60 | 88 ms | 均匀 |
| 先导出再播放，第 2 次 | 58 | 237 ms | 均匀 |
| 先导出再播放，第 1 次 | 50 | 651 ms | 平均 29.4 帧每秒，有两处约 150 ms 的迟滞 |

结论分两半：

- **最严重的那几种表现（每秒只画一帧、定时器停 20 秒）在前台没有再出现。** 判断是窗口在后台被遮挡时 Chromium 的节流，属于测试方式的问题——这是从“前台不再出现”推出来的，没有直接证实。观察到一次被遮挡的窗口每秒只刷新一帧而声音时钟照常走，所以 `main.ts` 里“窗口在后台时播放照常进行”的注释对画面可能不成立。
- **剩下的迟滞找到了位置，没有修**（记为 PERF-07）：CPU 采样里应用自己最忙的函数是 `Timeline.tsx:157` 的订阅——播放时让时间线跟随播放头“翻页”，改 `scrollLeft` 并更新视口状态（一次运行占 3.5%，另一次 12%），同时 `getContext` 占 9%，即翻页后画布在重绘。影响是播放时画面偶尔顿一下（前台最长 0.65 秒），声音不受影响。为什么“先导出再播放”更容易出现，我的推断是前一个很短的项目把时间线缩放留在了很大的一档，使翻页更频繁；**缩放值没有直接测量，这一条是推断**。

**仍然没有验收的**：导入真实媒体、播放、录制、接了真实模型的 Copilot、浅色主题、其余对话框和面板的逐个控件、与上一轮截图的逐像素对比。看了 3 张截图（编辑器、右键菜单、Copilot），没有发现错位或溢出，但这不是逐屏验收。
